# smm-timescale-compare

방법 정의, 신뢰도 규칙, 임의로 정한 기준값, 해석 점검 항목, 시험용 입력은 `references/research.md`에 있다. 작업 전에 읽는다.

README.md §5 "반복 작업"(기준 계산 1번)만 다룬다. 장기 자료 분석과 합성 자료 실험(2–4번)은 범위 밖이다.

## 입력
- 분석 연월 `YYYYMM`, 위도, 경도 (각 1개)
- 자료 경로: `/land1/ERA5/daily/land/YYYYMM_land.nc`
- 변수: `swvl1`(0–7 cm, m³/m³)로 고정. 강수(`mtpr`)와 해양 격자 판별용 `sst`도 읽는다.

## 지켜야 할 규칙
0. 연월이나 위경도가 없으면 추정하지 말고 묻는다. 해당 연월 파일이 없으면 없음을 알리고 멈춘다.
1. 원본 nc 파일은 수정하지 않는다. 읽기 전용으로 열고, 실행 전후에 크기와 수정 시각(`stat -c '%s %Y'`)이 같은지 확인한다.
2. 계산은 고정 스크립트 `.claude/skills/smm-timescale-compare/scripts/compute_tsmm.py`로만 한다. 즉석에서 계산 코드를 새로 쓰지 않는다. 방법 정의는 references/research.md를 따른다.
   - `--input` 옵션은 시험 전용이다(references/research.md "시험용 입력"). 실제 분석에는 쓰지 않는다.
3. 원문 식을 확인하지 못한 방법은 계산하지 않는다. 임의로 단순화한 식으로 값을 내지 않는다.
   - Hybrid(McColl et al., 2019)는 현재 표에 "계산 안 함"과 이유만 적는다.
   - 원문 식을 사용자가 제공하거나 확인한 뒤에만 구현한다.
4. 비교표는 10개 방법을 한 줄씩 보여 준다.
   - Entin과 Interannual은 별도 행으로 둔다.
   - 적용할 수 없는 방법(N/A)과 계산하지 않은 방법("계산 안 함")은 구분해서 표시한다.
   - 사용자에게 요약할 때도 행을 합치지 않는다.
5. 각 방법에 `신뢰도`와 `신뢰도 근거` 칸을 둔다.
   - 등급(높음/중간/낮음/-)은 스크립트에 고정한 규칙으로만 정한다. 즉석에서 판단하지 않는다.
   - 이 등급은 "그 달 자료 안에서 값이 얼마나 안정적인가"를 뜻하며, 기후학적 메모리의 정확도가 아니다.
6. 해석과 사용자에게 보내는 요약 문장의 숫자는 모두 스크립트가 계산한 값을 그대로 인용한다.
   - 근거는 "해석용 수치" 표의 D 키나 비교표 값으로 단다. 손으로 계산하거나 반올림을 바꾸지 않는다.
   - 필요한 숫자가 표에 없으면 스크립트의 `derived_quantities()`에 추가한 뒤 다시 실행한다.
7. 자료로 확인하지 않은 정성적 주장은 쓰지 않는다. 예를 들어 "장마 시작" 대신 계산된 연속 습윤 구간(D25 등)을 인용한다. 어느 방법이 맞다고 결론 내지 않는다.

## 워크플로
단계 번호는 고정이다. 순서를 바꾸거나 건너뛰지 않는다. 각 단계의 **결과**는 사용자에게 보이게 꺼내 놓고, **관문**을 통과해야 다음 단계로 간다.

| # | 단계 | 꺼내 놓을 결과 | 관문 |
|---|---|---|---|
| 1 | 입력 확인 | 연월, 위경도, `ls -la` 결과, `stat -c '%s %Y'` 값(= 기록값) | 세 입력이 모두 있고 파일이 있다. 아니면 묻거나 멈춘다(규칙 0) |
| 2 | 계획 | `## 계획`의 계획 블록 | 사용자가 계획을 확인했다. `results/`에 커밋 안 된 변경이 있으면 처리 방법도 답했다 |
| 3 | 스크립트 실행 | 콘솔 마지막 `Wrote ...` 줄 | 종료 코드 0, 출력 파일 4개가 있다 |
| 4 | 격자 점검 | 사용한 격자, 요청 지점과의 거리, 육지 여부, 해안 여부 | 보고서에 `land: yes, sst is NaN`이 있다. 해안 격자면 그 사실을 적어 둔다 |
| 5 | 해석 작성 | 보고서 끝의 `## 해석` 절 | 모든 숫자 뒤에 D 키나 비교표 근거가 괄호로 있다 |
| 6 | 결과 점검 | `check_result.py` 출력 (`OK` 또는 `FAIL` 줄) | 종료 코드 0. 실패하면 `## 검증`의 재시도 규칙을 따른다 |
| 7 | 보고 | 아래 7단계 목록 | 없음 |

1. **입력 확인.** 파일이 있는지 확인하고, 원본의 크기와 수정 시각을 기록한다. 이 기록값은 6단계에서 쓴다.
   ```bash
   ls -la /land1/ERA5/daily/land/YYYYMM_land.nc
   stat -c '%s %Y' /land1/ERA5/daily/land/YYYYMM_land.nc
   ```
2. **계획.** `## 계획`의 블록을 보여 주고 "이대로 진행할까요?"라고 묻는다. 사용자가 확인해야 3단계로 간다. `results/`에 커밋 안 된 변경이 있으면 처리 방법도 함께 묻는다.
3. **스크립트 실행** (저장소 최상위에서):
   ```bash
   python .claude/skills/smm-timescale-compare/scripts/compute_tsmm.py YYYYMM LAT LON --outdir results
   ```
   출력: `results/tsmm_YYYYMM_<lat>N_<lon>E` 의 `.md`(보고서), `.csv`(비교표), `_derived.csv`(해석용 수치, D 키), `_timeseries.csv`(지점 시계열)
4. **격자 점검.**
   - 사용한 격자와 요청 지점의 거리를 본다. 위경도 각각 가장 가까운 0.25° 격자를 쓴다.
   - 그 격자가 육지인지 본다(보고서에 `land: yes, sst is NaN`). 해안 지점이면 주변 격자가 바다일 수 있으니 결과에 함께 적는다.
5. **해석 작성.** 보고서 끝에 `## 해석` 절을 붙이고, 모든 숫자 뒤에 근거(D 키 또는 비교표 값)를 괄호로 단다. 다룰 항목은 references/research.md의 "해석 점검 항목"을 따르고, 결론에 한 달 자료의 한계(기후학적 메모리 길이로 쓰지 않음)를 적는다. 스크립트를 다시 실행하면 해석 절이 지워지므로 마지막 실행 뒤에 붙인다. 근거 문장의 `|` 문자는 Markdown 표를 깨므로 `abs(r)`처럼 쓴다.
6. **결과 점검.** `## 검증`의 명령을 실행한다. 비교표 행 수·열 수, 신뢰도 형식, 해석 숫자와 D 키, 시계열 결측, 원본 크기·수정 시각을 한 번에 본다. 통과한 뒤 숫자와 키 값의 대조가 필요하면 `## 서브에이전트`에 맡긴다.
7. **보고.** 다음 순서로 알린다.
   - 사용한 격자와 육지 여부
   - 10행 비교표 (값, 신뢰도, 근거 요약)
   - 해석의 핵심
   - 사용자가 확인해야 할 가정 (references/research.md의 "임의로 정한 기준값")
   - 원본 파일이 바뀌지 않았다는 확인 (`check_result.py`의 `OK` 줄)
   - 생성 파일 경로

## 계획
2단계에서 실행 전에 다음 블록을 보여 준다. 값은 1단계에서 확인한 것만 쓰고 추정하지 않는다.

```
연월:        YYYYMM
위경도:      LAT N, LON E  (요청값; 사용할 격자는 실행 후 4단계에서 확인)
읽을 파일:   /land1/ERA5/daily/land/YYYYMM_land.nc  (읽기 전용, 기록값 SIZE MTIME)
저장할 파일: results/tsmm_YYYYMM_<lat>N_<lon>E.md
             results/tsmm_YYYYMM_<lat>N_<lon>E.csv
             results/tsmm_YYYYMM_<lat>N_<lon>E_derived.csv
             results/tsmm_YYYYMM_<lat>N_<lon>E_timeseries.csv
             (각 파일: 새로 만듦 / 기존 파일 덮어씀)
results/ 상태: git status --porcelain results/ 결과 (없으면 "변경 없음")
```

- `<lat>`, `<lon>`은 요청값을 소수 둘째 자리로 쓴 것이다(스크립트의 `{lat:.2f}`).
- `git status --porcelain results/`에 줄이 하나라도 있으면 커밋 안 된 변경이 있는 것이다. 해당 파일 목록을 보여 주고, 저장할 파일과 겹치는지 표시한다. 그런 다음 다음 중 무엇을 할지 묻고 답을 기다린다.
  1. 그대로 덮어쓰고 진행
  2. 사용자가 먼저 커밋하거나 백업한 뒤 진행
  3. 중단
- 변경이 없어도 계획 블록을 보여 준 뒤 "이대로 진행할까요?"라고 묻고, 사용자가 확인하면 3단계로 간다.

## 검증
6단계에서 저장소 최상위에서 실행한다. `SIZE MTIME`은 1단계의 기록값이다.

```bash
python .claude/skills/smm-timescale-compare/scripts/check_result.py \
    results/tsmm_YYYYMM_<lat>N_<lon>E --expect-stat "SIZE MTIME"
```

| 항목 | 점검 내용 |
|---|---|
| `table` | CSV와 보고서 비교표가 각각 10행인지, Entin과 Interannual이 별도 행인지, 보고서 표의 모든 행이 7열인지 |
| `reliability` | 신뢰도가 높음/중간/낮음/- 중 하나인지, 값이 없는 행만 `-`인지, 근거가 비어 있지 않고 파이프 문자가 없는지, N/A와 "계산 안 함"이 구분되는지, Hybrid가 "계산 안 함"인지, 보고서와 CSV의 등급이 같은지 |
| `interp` | `## 해석`이 있는지, 해석의 숫자가 모두 스크립트 출력에 있는지, 인용한 D 키가 모두 `_derived.csv`에 있는지 |
| `timeseries` | 결측값이 없는지, 날짜가 하루씩 이어지고 해당 달 전체를 덮는지, 행 수가 D03(N)과 같은지 |
| `source` | 보고서 `File:` 줄의 원본 크기와 수정 시각이 `--expect-stat`과 같은지 |

- 종료 코드 0: 모두 통과했다. 마지막 줄은 `OK — ...`다.
- 종료 코드 1: 하나 이상 걸렸다. 문제마다 `FAIL [항목] 이유` 한 줄이 나온다.
- 종료 코드 2: 인자가 잘못됐거나 결과 파일이 없다.
- 이 스크립트는 파일을 읽기만 한다.

**재시도 규칙.**
- 걸리면 `FAIL` 줄을 사용자에게 보여 주고 원인을 고친 뒤 6단계를 다시 실행한다.
  - 해석 문제(`interp`)는 해석 절만 고친다.
  - 출력 자체가 문제면 원인을 고치고 3단계부터 다시 한다. 이때 해석 절이 지워지므로 5단계도 다시 한다.
- 같은 결과에 대해 실패가 2번을 넘으면, 즉 3번째 실패에서 고치지 말고 멈춘다. 그때까지의 `FAIL` 줄과 각각 시도한 수정을 보여 주고 어떻게 할지 묻는다.
- 예외로 `source`가 걸리면 원본이 바뀐 것이므로 고치지 않고 첫 실패에서 바로 멈춰 알린다.
- 이 스크립트는 숫자가 출력 어딘가에 있는지만 본다. 각 숫자가 괄호 속 키의 값과 같은지는 따로 대조한다(`## 서브에이전트`).

## 훅·권한
- 원본 `/land1/...` nc는 읽기만 한다(규칙 1). 쓰기는 `results/`에만 한다. 시험 파일과 시험 결과는 저장소 밖 `~/compare/testdata/`에 둔다.
- 짐작한 값은 쓰지 않는다. 연월·위경도가 없으면 묻고(규칙 0), 기준값을 바꿔야 하면 사용자에게 확인한다.
- 실행하는 명령은 두 스크립트(`compute_tsmm.py`, `check_result.py`)와 `ls`, `stat`, `git status`다.
- 커밋과 푸시는 사용자가 요청할 때만 한다.
- 현재 이 저장소에는 `.claude/settings.json`이 없다. 그래서 훅이 없고, 결과 점검은 훅이 아니라 6단계에서 직접 실행한다.
- 아래는 이 스킬에 맞춘 **예시**다. 쓰려면 사용자가 `.claude/settings.json`에 직접 넣는다.
  - `permissions.deny`는 Edit/Write 도구로 `/land1` 아래 파일을 고치지 못하게 막는다. 절대 경로는 `//`로 시작한다.
  - `PreToolUse` 훅은 셸 명령이 `/land1` 아래 파일을 지우거나(`rm`, `mv`), 쓰거나(`>`, `tee`, `dd`, `truncate`, `touch`), 속성을 바꾸려 하면(`chmod`, `chown`, `ln`, `ncatted`) 종료 코드 2로 막는다. `stat`, `ls`, 스크립트의 읽기는 막지 않는다. `jq`가 필요하다.
  - `ask`는 커밋과 푸시 전에 확인을 받게 한다.

```json
{
  "permissions": {
    "allow": [
      "Bash(python .claude/skills/smm-timescale-compare/scripts/compute_tsmm.py:*)",
      "Bash(python .claude/skills/smm-timescale-compare/scripts/check_result.py:*)",
      "Bash(stat -c:*)",
      "Bash(ls -la /land1/ERA5/daily/land/:*)",
      "Bash(git status:*)"
    ],
    "ask": [
      "Bash(git commit:*)",
      "Bash(git push:*)"
    ],
    "deny": [
      "Edit(//land1/**)",
      "Write(//land1/**)",
      "NotebookEdit(//land1/**)"
    ]
  },
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "jq -r '.tool_input.command // empty' | grep -qE '(^|[;&|[:space:]])(rm|mv|touch|truncate|chmod|chown|tee|dd|ln|ncatted)[[:space:]][^;&|]*/land1|>[[:space:]]*/land1' && { echo '차단: 원본 /land1 쓰기·지우기 금지 (smm-timescale-compare 규칙 1)' >&2; exit 2; } || exit 0"
          }
        ]
      }
    ]
  }
}
```

## 서브에이전트
기본적으로 쓰지 않는다. 지점이 하나이고 단계가 순서대로 이어지기 때문이다. 쓰는 경우는 하나뿐이다. 6단계가 통과한 뒤 해석의 숫자를 인용한 키의 실제 값과 대조하는 일을 맡긴다. 주 에이전트의 결론이나 기대를 넘기지 않고 파일 경로만 넘긴다.

- **목표:** `## 해석` 절의 숫자마다 괄호 속 D 키(또는 비교표 값)의 실제 값과 같은지 확인한다. 반올림까지 같아야 일치로 본다.
- **입력:** 보고서 `.md` 경로와 `_derived.csv` 경로, 필요하면 비교표 `.csv` 경로
- **결과 모양:** 아래 표 하나와 마지막 줄 `불일치 N개`. 다른 설명은 붙이지 않는다.

  | 숫자 | 인용한 키 | 키의 실제 값 | 일치 여부 |
  |---|---|---|---|
  | 38 | D17 | 38 | 일치 |
  | 2.7 | D09 | 2.7 | 일치 |

  - 키 없이 쓴 숫자는 `인용한 키`에 `(없음)`, `일치 여부`에 `키 없음`이라고 적는다.
  - 키 하나에 여러 숫자가 들어 있으면 해당하는 부분 값을 적는다. 예: D25 → `163.4 mm`
- **도구:** 파일 읽기만 한다(Read). 셸, 스크립트 실행, 편집, 웹 검색은 쓰지 않는다.
- **경계:**
  - 파일을 수정하거나 새로 만들지 않는다.
  - 해석이 맞는지, 표현이 적절한지, 어느 방법이 맞는지는 판단하지 않는다. 값이 같은지만 본다.
  - 불일치를 고치지 않고 표에만 적는다. 고치는 일은 주 에이전트가 `## 검증`의 재시도 규칙에 따라 한다.
